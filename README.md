# Directum Sales Tester — инструкция

Веб‑сервис для проверки знаний менеджеров по продажам: выбор темы, голосовой ответ, распознавание (Whisper), оценка по эталону (LLM) и сохранение в БД.

---

## Быстрый старт

1. **Скопируйте конфиг и задайте свои значения:**
   ```bash
   copy .env.example .env
   ```
   Откройте `.env` и укажите:
   - `ADMIN_LOGIN` и `ADMIN_PASSWORD` — логин и пароль входа в админку
   - `OPENAI_API_KEY` — ключ OpenAI для Whisper (распознавание голоса)
   - `OPENROUTER_API_KEY` — ключ OpenRouter для языковых моделей (оценка ответов, анализ)

2. **Запуск одной командой:**
   ```bash
   docker compose up -d
   ```
   Сервис будет доступен по адресу **http://localhost:8033** и будет работать до остановки (`docker compose down`).

3. **Проверка:**
   - Главная страница (тестирование): http://localhost:8033/
   - Админка: http://localhost:8033/admin (логин и пароль из `ADMIN_LOGIN` / `ADMIN_PASSWORD`).

## Настройка переменных окружения (.env)

| Переменная | Описание |
|------------|----------|
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` | Подключение к PostgreSQL (по умолчанию уже подходят для Docker). |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | Логин и пароль входа в админку. Обязательно смените в проде. |
| **Whisper (распознавание голоса)** | |
| `OPENAI_API_KEY` | Ключ OpenAI для доступа к Whisper. |
| `OPENAI_BASE_URL` | URL API OpenAI (по умолчанию `https://api.openai.com/v1`). |
| **Языковые модели (оценка, анализ)** | |
| `OPENROUTER_API_KEY` | Ключ OpenRouter для оценки ответов и пакетного анализа. |
| `OPENROUTER_BASE_URL` | URL OpenRouter (по умолчанию `https://openrouter.ai/api/v1`). |
| `LLM_MODEL` | Модель через OpenRouter (по умолчанию `openai/gpt-5-mini`). |
| `SUPABASE_URL`, `SUPABASE_KEY` | Нужны только для однократной миграции данных из Supabase (см. ниже). |

## Миграция данных из Supabase

Если раньше использовались n8n и Supabase:

1. В `.env` задайте `SUPABASE_URL` и `SUPABASE_KEY` (anon key проекта Supabase).
2. Запустите контейнеры: `docker compose up -d`.
3. Выполните миграцию один раз:
   ```bash
   docker compose exec app python migrate.py
   ```
   Будут перенесены темы и сессии из таблиц `n8n_sales_test_themes` и `n8n_sales_test_sessions` в локальную PostgreSQL.

После миграции `SUPABASE_*` можно убрать из `.env`, если Supabase больше не нужен.

## Как пользоваться

### Для продавцов (сдача зачёта)

1. Откройте http://localhost:8033/
2. Введите ФИО и нажмите «Далее».
3. Выберите тему (ценностное предложение) для зачёта.
4. Нажмите «Нажать и говорить», запишите голосовой ответ, затем «Остановить запись».
5. Нажмите «Отправить на проверку». После обработки отобразится оценка и комментарий ИИ.

### Для администратора

1. Откройте http://localhost:8033/admin и введите логин и пароль из `ADMIN_LOGIN` / `ADMIN_PASSWORD`.
2. **Результаты** — таблица с пагинацией и фильтрами (ФИО, тема, оценка, даты). Выбор строк и «Запустить анализ» — пакетный анализ выбранных ответов.
3. **Темы** — добавление, редактирование, включение/отключение тем для зачёта, удаление.
4. **Промты** — версионируемые промты для проверки знаний:
   - «Создать черновик промта» — новая версия с шаблоном по умолчанию;
   - редактирование черновика, «Проверить на ответе» — применить черновик к сохранённому ответу из базы;
   - «Сделать активным» — этот промт будет использоваться при проверке новых ответов (одновременно активен только один промт).
5. **Анализ** — выберите ответы на вкладке «Результаты» и нажмите «Запустить анализ» для потокового анализа.

## Остановка и перезапуск

- Остановить: `docker compose down`
- Запустить снова: `docker compose up -d`
- Данные в БД сохраняются в Docker-томе `pgdata` (теряются только при `docker compose down -v`).

---

## Устранение неполадок

**Ошибка «password authentication failed for user "salestester"»**  
Пароль в `.env` (`DB_PASSWORD`) не совпадает с паролем, под которым был впервые создан том PostgreSQL. Варианты:
- Подставить в `.env` тот пароль, с которым БД создавалась (например, `changeme`), **или**
- Пересоздать БД с текущим паролем (все данные в БД будут удалены):
  ```bash
  docker compose down -v
  docker compose up -d
  ```

**После смены пароля БД** всегда выполняйте `docker compose down -v` и затем `docker compose up -d`, иначе контейнер PostgreSQL продолжит использовать старый пароль из тома.
